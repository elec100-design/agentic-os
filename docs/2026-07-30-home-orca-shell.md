# 홈 화면 Orca ADE식 3분할 셸

Orca ADE(https://www.onorca.dev/) 참고. 기존 `docs/2026-07-30-orca-layout-wireframe.md`는
프로젝트 상세(`project.html`)에 **좌측** 채팅 레일을 붙이는 안이었고, 이 문서는 홈
(`index.html`) 전체를 **우측** 채팅·세션 레일 + 중앙 멀티 탭 + 최하단 작업 큐 상태바로
재구성한 결과를 기록한다.

## 1. 레이아웃

```
┌──────────────┬────────────────────────────────┬──────────────────┐
│ sidebar      │ 중앙 메인뷰                     │ 우측 레일         │
│ 260px        │ .orca-home-ws                  │ .orca-side-rail  │
│              │  ┌ 탭바(작업 탭) ────────────┐  │ 360px            │
│ 브랜드        │  │ #1 프롬프트… ● │ #2 … ✕  │  │ [채팅 | 세션]     │
│ 🗂 비전 보드  │  └──────────────────────────┘  │ ─ 채팅 ─         │
│ 메모리        │  탭 내용 = /partials/job/{id}   │  최근 요청 말풍선  │
│ 사용량        │  (진행 로그 SSE + 산출물 렌더)   │  + 컴포저        │
│ ⚙︎ 설정      │                                │ ─ 세션 ─         │
│              │  탭이 없으면 히어로 화면          │  채널 목록        │
├──────────────┴────────────────────────────────┴──────────────────┤
│ ▲ 작업 큐   실행 2 · 대기 1 · 완료 5          ← 접힘(기본)         │
└──────────────────────────────────────────────────────────────────┘
```

- **좌측 사이드바**: 기존 `.sidebar` 그대로. 채널(세션) 목록만 우측 레일로 이동했다.
  ≥901px에서는 `position: relative` flex 트랙, 그 아래는 기존 오프캔버스 동작 유지.
- **중앙 `.orca-home-ws`**: 작업 하나가 탭 하나. 탭 내용은 `/partials/job/{id}` 조각이고
  `job-view.js`가 마크다운 렌더 + `/jobs/{id}/stream`(SSE) 구독을 맡는다. 열린 탭은
  localStorage에 남아 새로고침 후 복원된다(HEAD로 존재 확인 후 죽은 탭은 버림).
- **우측 `.orca-side-rail`**: 280~560px 드래그 리사이즈 + 접기(localStorage 유지).
  `채팅` 탭은 최근 요청 말풍선 + 기존 컴포저, `세션` 탭은 `/partials/channels`.
  <1024px에서는 오른쪽에서 슬라이드되는 오프캔버스 + 스크림.
- **최하단 `.orca-statusbar`**: 기본 접힘. 접힌 상태에서도 요약 카운트는 보인다.
  펼치면 기존 `/partials/jobs` 테이블이 그대로 나온다(최대 42vh 스크롤).

## 2. 데이터 흐름 — 폴링을 늘리지 않았다

상태바 요약 카운트, 채팅 탭 말풍선, 열린 탭의 상태 점이 **모두** 이미 3초마다 도는
`#jobs`(`/partials/jobs`) 스왑 하나에서 파생된다. `home.js`가 `htmx:afterSwap`에서
테이블을 읽어 세 곳을 갱신한다 — 새 엔드포인트도, 추가 폴링도 없다.

새로 추가한 서버 계약은 하나뿐이다:

| 엔드포인트 | 용도 |
|---|---|
| `GET/HEAD /partials/job/{id}` | 중앙 탭 내용. `partials/job_view.html` 조각. HEAD는 탭 복원 시 존재 확인용(`partials/task/{id}`와 같은 계약) |

`job.html`(단독 페이지)도 같은 조각을 include하므로 작업 상세 마크업은 한 곳에만 있다.

## 3. 곁들여 고친 것

- `app.js`의 팝업 배치(`placePopup`): 기존 코드는 문서 좌표(`getBoundingClientRect() +
  scrollX/Y`) + `position: absolute` 조합이라 offsetParent가 body일 때만 맞았다. 컴포저가
  우측 레일(`position: absolute`인 `.orca-rail-panel`) 안으로 들어가면서 offsetParent 기준
  변환이 필요해졌고, 화면 하단에서 아래로 펼칠 공간이 없으면 위로 뒤집도록 했다.
  `#ws-popup`도 같은 로직을 복제하고 있었어서 한 함수로 합쳤다.
- `i18n.py`: 레일·탭바 문구 번역 추가. 기본 언어가 영어이므로 누락 시 한국어가 그대로
  노출된다 — `채팅`/`이전 탭`/`접기/펼치기`/`패널 너비 조절`은 프로젝트 상세 화면이
  이미 쓰던 미번역 문구였고 이번에 함께 채웠다.

## 4. 확인 범위

`tests/test_home_layout.py` 12개로 셸 구성 요소·컴포저 ID 보존·작업큐 기본 접힘·세션
이동·조각 계약, 그리고 2차 작업분(대화 렌더·이전 턴 트리밍·이어가기 모드 분기·JSON
응답·모바일 서랍 버튼 배치)을 검증한다. 이 저장소에는 헤드리스 브라우저가 없어 실제 픽셀 렌더링은
`test_responsive_breakpoints.py`와 같은 한계로 검증하지 못한다.

## 5. 후속(같은 날 2차) — 탭 내용을 대화로, 그리고 모바일 서랍 버튼

### 5.1 "불러올 수 없습니다."의 원인

탭이 전부 이 메시지만 띄웠던 이유는 코드가 아니라 **실행 중인 프로세스**였다.
`GET /partials/job/{id}`는 이번 작업분(미커밋)에 새로 추가된 라우트인데, launchd의
uvicorn은 `--reload` 없이 돈다(`launchd/agentic-os.plist.template`). 템플릿·정적
파일은 요청마다 디스크에서 읽히므로 새 셸 HTML/JS는 이미 보였지만, `app/main.py`는
기동 시점 모듈이 그대로여서 404가 났다(`data/aos.log`에 `GET /partials/job/193 404`).

→ **코드 배포 후 서비스 재시작이 필요하다.** 재시작하면 같은 프로세스의 워커가 돌리던
실행 중 작업도 함께 끊기므로, 실행 중인 작업이 없을 때 재시작할 것.

함께 진단이 쉬워지게 탭의 실패 상태를 고쳤다: 404와 네트워크 오류를 구분해 사유를
쓰고(`서버가 아직 이 화면을 모릅니다(재시작 필요)`) `다시 시도` 버튼을 붙였다.

### 5.2 탭 = 대화 + 이어서 작업

`partials/job_view.html`을 "프롬프트 + 출력" 나열에서 **말풍선 대화**로 바꿨다
(`.chat-thread`는 노트 뷰가 쓰던 것을 그대로 재사용).

- 이전 턴은 서버가 연결된 스레드 노트에서 읽어 `<script type="application/json">`으로
  싣고 `job-view.js`가 마크다운으로 렌더한다. 노트는 작업이 **끝난 뒤** 기록되므로
  끝난 작업이면 노트의 마지막 한 쌍이 이 작업 자신이라 프롬프트로 확인해 잘라낸다
  (`_job_view_ctx`). 실행 중인 작업의 노트에는 아직 자기 턴이 없어 그대로 쓴다.
- 끝난 작업에는 `.job-followup` 컴포저가 붙는다. 세션 재개가 가능한 에이전트면
  `session_id`+`origin_note`로 세션을 이어받고(노트에 N차로 계속 쌓인다), hermes·
  antigravity·gemini처럼 재개가 불가능하면 `context_note`로 이 대화를 컨텍스트로
  붙여 같은 에이전트에게 넘긴다. 판정 기준은 `note_view`와 동일하다.
- 제출은 페이지를 떠나지 않는다: `POST /jobs`가 `Accept: application/json`이면
  리다이렉트 대신 `{"job_id": …}`를 준다. 홈에서는 `window.openJobTab(새 id, 이전 id)`가
  새 탭을 열고 이전 탭을 닫아 한 탭에서 대화가 계속되는 것처럼 보이게 한다. 단독
  페이지(`job.html`)에는 `openJobTab`이 없어 `/jobs/{새 id}`로 이동한다.

### 5.3 모바일 좌·우 서랍 버튼

두 서랍을 여닫는 버튼을 **화면 아래 양쪽 모서리에 대칭으로** 놓았다(48px, 상태바 위).
상단은 탭바가 쓰고, 아래 모서리는 한 손으로 둘 다 닿는다.

- 좌측(`#nav-toggle`)은 `body.orca-home` ≤900px에서만 하단 좌측으로 내려온다(다른
  화면의 좌상단 햄버거는 그대로). 내려온 만큼 `.orca-home-main`·`.sidebar`의
  햄버거 회피 여백(3.4/3.6rem)도 되돌렸다.
- 우측(`#home-rail-toggle`)은 같은 버튼으로 열고 닫는다. 열려 있는 동안은 두 버튼 모두
  서랍 위에 겹치지 않게 감추고, 닫기는 레일 헤드의 ✕(`#home-rail-close`)·스크림 탭·ESC로
  한다. 오프캔버스 구간에서는 폭 접기(›)가 의미 없으므로 숨긴다.
- 좌측 서랍도 스크림(`body.orca-home.nav-open::before`)을 얻어 밖을 탭하면 닫힌다는
  신호를 준다. 실제 닫기는 `app.js`의 문서 클릭·ESC 핸들러(모든 화면 공통)가 처리한다.
- 한쪽을 열면 다른 쪽을 닫아 두 서랍이 겹치지 않는다. 채팅 말풍선을 눌러 탭을 열면
  레일이 자동으로 닫힌다(기존 `closeRailOverlay` 동작).

## 6. 스코프 밖

- 프로젝트 상세(`project.html`)의 좌측 `.orca-chat-rail`은 건드리지 않았다. 홈과 좌우가
  다르므로, 통일이 필요하면 별도 작업으로 결정할 것.
- 중앙 탭의 "코드 뷰"는 작업 산출물 마크다운 렌더(코드 블록 하이라이트 포함)로 대신했다.
  편집 가능한 에디터는 범위 밖.
